# Ashes of Empires, Loop Lessons

Living memory for the Muse takeover build loop (started 2026-10-15, Jash's order). Read at the start of every run. Append at the end of every run: what failed and why, what pattern worked, what to try or avoid next time. If a lesson proves wrong, strike it through with a dated note instead of deleting it.

## Lessons

- 2026-10-15, reconciliation discovery: the GitHub branch state in the takeover brief (about 10 ahead, 4 behind) was stale by the time the first takeover run checked it. The branch claude/adoring-johnson-cf5bmq is in fact 136 commits ahead of remote master and 0 behind, because it was rebased onto master's Cycle 6 step 5 commit and then kept building through Cycles 7 to 17 on 2026-10-13 and 2026-10-14. Lesson: never trust a brief's branch counts. Measure the branch with the compare API at the start of reconciliation and log the measured counts.
- 2026-10-15, gh.py path bug: the GitHub fetch script inserts a wrong sys.path (templates/skill/bin) and fails with ModuleNotFoundError for dynamic_credentials on a plain run. Setting PYTHONPATH to /opt/muse/skills/custom-connector-setup/bin makes the exact script named in the mission work without editing it. Use that prefix for every gh.py call in this loop.
- 2026-10-15, port in authored slice order, but assess before replacing: the branch's first reconciliation slice added a balance harness, but master gained its own committed harness in Cycle 6 step 5 (commit 797b1b8) that reproduces the verified step 4 numbers. Overwriting it blindly would have traded a verified harness for an unverified one. Diff before treating a branch item as unique, exactly as the mission warned for tools/balance.js.
- 2026-10-15, test-only slices are the safest first port: the drawn in defender reversal test (slice 2) applied as a pure append, passed on master unchanged (40 of 40), and changed no balance numbers. When a reconciliation contains a test that pins a behavior master already claims, port the test early; it turns a claimed behavior into a pinned one.
- 2026-10-15, a branch harness that gates on profiles that fail is information, not a defect to hide: the branch slice 1 harness records that its no factory script loses seed 31337 and its factory path won only 1 of 8 on the pre slice sim. Those failures are what slices 4 (research clock) and 5 (lines paid before factories) were built to fix. Do not port the gating harness before the sim slices it depends on, or the repo will carry a red gate with no fix in the same step.
- 2026-10-15, gh.py fetch is not idempotent over a dirty destination: a leftover extracted directory in /tmp/ashes-gh-sync made the fetch fail with a rename Directory not empty error partway through, leaving a half synced copy that looked like a real diff. Lesson: rm -rf /tmp/ashes-gh-sync before every fetch, and never trust a diff from a fetch that exited non-zero.
- 2026-10-15, branch commit patches are fetchable one at a time through the GitHub commits API with the same surrogate credential gh.py uses: GET /repos/jashshah854-a11y/ashes-game/commits/<sha> returns the full per file patch. That is the clean way to port one authored slice verbatim without fetching the whole 136 commit branch.
- 2026-10-15, reconciliation step 3: a branch patch authored in slice order still applies verbatim after master has diverged by its own port commits (compare now reads 136 ahead, 2 behind; the 2 behind are the slice 2 and slice 3 port commits). Check fidelity by matching the local diff stat against the branch patch's per file counts (slice 4: sim 12 insertions and 2 deletions, test 16 insertions) before running tests.
- 2026-10-15, a timing parity fix can leave every standard balance band identical and still be real: slice 4 changed no number in master's harness output, and its effect is pinned only by its dedicated research clock test. Do not judge a slice by whether the balance table moved.
- 2026-10-15, do not import branch balance claims for profiles master's harness does not run: the branch slice 4 message quotes sensible without factories and factories profiles that exist only in the branch harness dropped in slice 1. Record those as branch claims, verify master with master's harness plus the ported test, and say plainly which is which in the log.
- 2026-10-15, reconciliation step 4: a slice can be portable in code and unportable in its harness change at the same time. Slice 5's sim, UI, and test applied verbatim (diff stats matched the branch patch exactly), but its tools/balance.js change flips a profile inside a PROFILES table master's harness never had. Check a slice file by file, not as a bundle: port what matches master's structure, and log the rest as not ported with the structural reason, instead of importing a foreign harness to make the patch complete.
- 2026-10-15, payment order fixes may also leave the standard bands untouched: slice 5, like slice 4, changed no number in master's harness output, because master's sensible games end on day 25 before factory upkeep can outrun income. The dedicated order test is the evidence; the bands are only a regression check. Do not read unchanged bands as the slice doing nothing, and do not claim the branch's dramatic band movements (which came from its longer games) for master.
- 2026-10-16, reconciliation step 5: a docs only slice can be the least portable slice in a set, because docs carry numbers. Slice 6's text was mostly branch harness results (200 seed runs, a no factory profile, a click through browser unlock) that master never reproduced. Porting docs verbatim would have laundered branch claims into master's honest list. Rule: every number in a ported doc must trace to a master run in the same step, or the sentence does not come across.
- 2026-10-16, stale taste items are a real defect class: master's DECISIONS_FOR_JASH.md item 1 still quoted Cycle 5 capture days two cycles after they were superseded, and nothing in the test suite can catch that. When a step changes the headline balance numbers, grep the decisions and backlog files for the old numbers in the same step.
- 2026-10-16, Cycle 7 step 1 port: a branch file at a cycle's first commit is not the file the cycle closed with. The branch lore arrived with a gauge contradiction its own judge later fixed in a one line commit (a62608a). Before porting any branch cycle's early step, check for later commits touching the same files inside that cycle and fold their corrections in, naming each fold in the log; otherwise the port knowingly re-ships a flagged defect.
- 2026-10-16, a diff against the branch file at the ported commit isolates interleaved slices for free: diffing master's sim against the branch sim at the Cycle 7 step 1 commit showed exactly three differences (a header wording change, the beat hooks being ported, and the earlier judge flag 1 defender draw block not being ported). That one diff both proved the port's fidelity and surfaced the pending flag 1 item with its exact code location. Use it as the standard fidelity check when a branch commit bundles work from more than one slice.
- 2026-10-16, branch judge flag 1 port: verify a ported test is non vacuous by running the new suite once against the pre port sim in a scratch copy (git show HEAD:js/sim.js into a copied tree). The mirror test failed there and passes on the ported sim, which is stronger evidence than a green suite alone, and it costs one extra test run. Do this for every test that claims to pin a fix.
- 2026-10-16, a documented rule can be only half true in code: Cycle 6 documented that snapshot occupants defend their province even if ordered elsewhere, and master's earlier tests pinned that for the case where the attacker's group sorted first. The asymmetric case (the defender's own attack sorting first) was invisible to those tests because group sort order is by origin province id, which quietly favours the west side. When a rule depends on sort order, test the mirror image, not only the natural case.
- 2026-10-16, Cycle 7 step 2 port: overlapping hunks make per patch insertion sums lie. The four patches applied this run sum to 4 more insertions than the net diff against master, because the judge correction hunks rewrite lines the step itself added. Do not flag that as a fidelity problem or chase it: fetch the branch files at the last folded commit and diff the finished files byte for byte. All four files matched exactly, which settles what patch arithmetic cannot.
- 2026-10-16, a committed browser check can depend on tooling this environment does not have: tools/lore-check.js expects Playwright at paths that do not exist here, while the older tools/browser-check.js drives Chromium over raw CDP and works anywhere. The check still ran at full strength by installing playwright-core into /tmp and pointing PLAYWRIGHT and CHROME at it. Lesson: before declaring a ported check unrunnable, try satisfying its driver from /tmp; and when writing future checks, prefer the raw CDP pattern of browser-check.js so the next environment needs nothing installed.
